## 2. المفهوم التقني — Web App vs Website

HealPath **ليس موقعاً إلكترونياً** — بل **تطبيق ويب متكامل** بالخصائص التالية:

| الخاصية | الموقع التقليدي | HealPath (تطبيق ويب) |
|---|---|---|
| **التفاعلية** | صفحات ثابتة | تجربة تفاعلية كاملة بدون إعادة تحميل |
| **حالة المستخدم** | محدودة | Session كامل، ملف شخصي، إشعارات حية |
| **البيانات** | خارجية | محفوظة كاملاً داخل حاوية Docker |
| **الأداء** | تحميل صفحات | Single Page App — سرعة تطبيق أصيل |
| **النشر** | استضافة تقليدية | Docker Container — قابل للنشر في أي مكان |
| **الاستقلالية** | يعتمد على خدمات خارجية | مكتفٍ ذاتياً — قاعدة البيانات والملفات داخله |

## 4. هيكل المنصة والمستخدمون

### 4.1 بوابة المريض (Patient Portal)

**آلية الدخول:**
- المستخدم الجديد: يسجل حساباً بالبريد الإلكتروني + كلمة المرور
- المستخدم المسجل: يدخل بالبريد الإلكتروني + كلمة المرور

**الخدمات المتاحة:**
- تصفح الأقسام الطبية والأطباء وحجز المواعيد
- الدفع النقدي عند الوصول (المرحلة الأولى)
- الصيدلية الإلكترونية
- المساعد الطبي الذكي
- المحتوى التثقيفي الصحي
- قسم التوظيف

### 4.2 لوحة تحكم المستشفى — 4 أدوار

| الدور | الصلاحيات |
|---|---|
| **المدير العام (Super Admin)** | كامل الصلاحيات على جميع أقسام التطبيق |
| **الطبيب (Doctor)** | يرى حجوزاته الخاصة فقط + تأكيد / إلغاء مواعيده |
| **مدير الصيدلية** | إدارة المخزون الدوائي + الطلبات الواردة + المبيعات |
| **مسؤول التوظيف** | نشر الشواغر + استقبال الطلبات + إدارتها |

## 5. الأقسام الطبية

| القسم | الاختصاص |
|---|---|
| **قسم العظمية** | أمراض وجراحات العظام والمفاصل والعمود الفقري |
| **قسم الصدرية** | أمراض الرئتين والجهاز التنفسي والصدر |

> **قابل للتوسع:** يمكن إضافة أقسام جديدة من لوحة التحكم دون تعديل الكود.

## 6. الميزات الكاملة

### 6.1 إدارة حسابات المرضى
- تسجيل: بريد + كلمة مرور + اسم + هاتف
- ملف المريض الشخصي (التاريخ المرضي، المواعيد السابقة)
- عرض الأطباء مع صورهم وخبراتهم
- حجز موعد مع الطبيب المختار
- الدفع نقدي عند الوصول (إلكتروني مستقبلاً)
- إشعارات تذكير بالمواعيد عبر البريد الإلكتروني

### 6.2 الصيدلية الإلكترونية
- متجر داخلي لشراء الأدوية
- بحث وفلترة الأدوية
- سلة مشتريات + تأكيد طلب
- دفع نقدي عند الاستلام
- إدارة المخزون من لوحة مدير الصيدلية

### 6.3 المساعد الطبي الذكي — الميزة المحورية

**المسار 1 — تحليل الأعراض نصياً:**
```
المريض: "عندي ألم في الركبة عند المشي"
   ↓ GPT-4
الرد: يُنصح بمراجعة قسم العظمية
      + زر "احجز موعداً الآن"
      ⚠️ تحليل استرشادي — لا يُغني عن الطبيب
```

**المسار 2 — قراءة نتائج التحاليل (صورة):**
```
المريض يرفع صورة نتيجة تحليل
   ↓ GPT-4 Vision
الرد: قراءة أولية للقيم + توصية بالقسم
      ⚠️ تحليل استرشادي أولي
```

**المرحلة الثانية (مستقبلاً):** تحليل الأشعة (X-Ray / MRI) بنماذج Computer Vision متخصصة.

### 6.4 قسم التوظيف
- إعلانات الشواغر (من مسؤول التوظيف)
- التقديم برفع السيرة الذاتية (PDF)
- إدارة الطلبات الواردة من لوحة التحكم

### 6.5 المحتوى التثقيفي الصحي
- مقالات ونصائح طبية دورية
- مرئية لجميع الزوار دون تسجيل
- إدارة المقالات من المدير العام

## 7. نموذج الإيرادات

| المصدر | الآلية | النسبة المقترحة |
|---|---|---|
| **حجوزات المواعيد** | عمولة على كل حجز مكتمل | 5% – 15% |
| **الصيدلية الإلكترونية** | عمولة على كل عملية بيع | 5% – 10% |

> **توصية:** فترة تجريبية مجانية عند الإطلاق لضمان اعتماد المستشفى للتطبيق — ثم تفعيل العمولة الكاملة.

## 8. تحليل السوق — سوريا

### 8.1 واقع الرعاية الصحية الرقمية
- السوق في مرحلة نمو مبكر للتحول الرقمي
- غالبية المستشفيات تعتمد أنظمة تقليدية أو ورقية
- طلب متزايد على الخدمات الصحية الرقمية
- انتشار الإنترنت والهواتف في المدن الكبرى

### 8.2 الفرصة السوقية
- غياب تام لحلول رقمية بذكاء اصطناعي في السوق المحلي
- لا يوجد منافس يجمع: توجيه ذكي + حجز + صيدلية في منصة واحدة
- حاجة فعلية لتسهيل الوصول للخدمات الطبية

### 8.3 مقارنة مع المنافس الرئيسي (ATSG)

| جانب | ATSG | HealPath |
|---|---|---|
| **طبيعة المنتج** | نظام HIS إداري تقليدي | تطبيق ويب متكامل بذكاء اصطناعي |
| **توجيه المريض** | غير موجود | ميزة محورية بـ GPT-4 |
| **تجربة المريض** | للإداريين فقط | واجهة مريض مباشرة وسهلة |
| **الصيدلية** | إداري فقط | متجر متكامل |
| **الذكاء الاصطناعي** | غائب | قلب التطبيق |
| **التسعير** | ترخيص مرتفع مسبق | عمولة مرنة على الأداء |

## 11. مخطط الواجهات — UI/UX Architecture

### 11.1 الخريطة العامة

```
┌──────────────────────────────────────────────────────────────┐
│                   HealPath Web Application                   │
├──────────────────────────┬───────────────────────────────────┤
│     بوابة المريض         │      لوحة تحكم المستشفى           │
│   (Patient Portal)       │     (Hospital Dashboard)          │
│                          │                                   │
│  👁 زوار (عرض فقط)        │  👤 المدير العام (كل الصلاحيات)   │
│  🏥 مرضى مسجلون          │  👨‍⚕️ الطبيب (حجوزاته فقط)         │
│                          │  💊 مدير الصيدلية                 │
│                          │  📋 مسؤول التوظيف                 │
└──────────────────────────┴───────────────────────────────────┘
```

### 11.2 صفحة الهبوط (Landing Page)
- Header: شعار + اسم المستشفى + تسجيل دخول / إنشاء حساب
- Hero: عنوان تعريفي + CTA "ابدأ الآن"
- الأقسام الطبية (للاطلاع فقط)
- بطاقات الأطباء (للاطلاع فقط)
- المقالات التثقيفية (مرئية للجميع)
- الشواغر الوظيفية (مرئية للجميع)
- Footer: تواصل + روابط

### 11.3 مسار الحجز

```
اختيار القسم → اختيار الطبيب → بروفايل الطبيب
→ اختيار التاريخ (تقويم تفاعلي) → اختيار الوقت
→ ملاحظات (اختياري) → ملخص الحجز
→ تأكيد (دفع نقدي عند الوصول)
→ شاشة تأكيد + إشعار بريد إلكتروني
```

### 11.4 المساعد الذكي (Floating Drawer)
- زر طاف في جميع صفحات التطبيق
- يفتح Drawer جانبي بدون مغادرة الصفحة
- محادثة نصية + رفع صورة تحليل
- نتيجة واضحة + زر حجز مباشر

### 11.5 قرارات تصميم الواجهة

| القرار | الخيار المعتمد |
|---|---|
| **نوع التطبيق** | SPA (Single Page Application) — تجربة تطبيق أصيلة |
| **المساعد الذكي** | زر طاف ثابت + Drawer جانبي |
| **عرض الأطباء** | بطاقات (Cards) بصورة واسم وتخصص |
| **واجهة المريض** | تنقل علوي (Top Navigation) |
| **واجهة المستشفى** | شريط جانبي (Sidebar) |
| **الاتجاه الافتراضي** | RTL (عربي) مع دعم LTR للإنجليزية |
