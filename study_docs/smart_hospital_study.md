## 3. هيكل المنصة والمستخدمون

### 3.1 بوابة المريض (Patient Portal)
الواجهة التي يتعامل معها المريض مباشرة:

**آلية الدخول:**
- المستخدم الجديد: يسجل حساباً جديداً بالبريد الإلكتروني + كلمة المرور
- المستخدم المسجل: يدخل البريد الإلكتروني + كلمة المرور مباشرةً

**الخدمات المتاحة:**
- تصفح الأقسام الطبية والأطباء وحجز المواعيد
- الدفع النقدي عند الوصول (المرحلة الأولى)
- الصيدلية الإلكترونية
- المساعد الطبي الذكي
- المحتوى التثقيفي الصحي
- قسم التوظيف (للباحثين عن عمل)

### 3.2 لوحة تحكم المستشفى (Hospital Dashboard) — 4 أدوار

| الدور | الصلاحيات |
|---|---|
| **المدير العام (Super Admin)** | كامل الصلاحيات على جميع أقسام النظام |
| **الطبيب (Doctor)** | يرى حجوزاته الخاصة فقط + تأكيد / إلغاء مواعيده |
| **مدير الصيدلية** | إدارة المخزون الدوائي + الطلبات الواردة + المبيعات |
| **مسؤول التوظيف** | نشر الشواغر + استقبال الطلبات + إدارتها |

## 4. الأقسام الطبية في المستشفى

المستشفى يضم الأقسام التالية — وكل قسم يعرض:
- اسم القسم ووصفه
- صور الأطباء وأسماءهم الكاملة
- تخصص كل طبيب ومدة خبرته
- جدول مواعيد الدوام
- إمكانية حجز موعد مباشر

| القسم | الاختصاص |
|---|---|
| **قسم العظمية** | أمراض وجراحات العظام والمفاصل والعمود الفقري |
| **قسم الصدرية** | أمراض الرئتين والجهاز التنفسي والصدر |
| **قسم الكلى** | أمراض الكلى وأمراض المسالك البولية |
| **قسم القلبية** | أمراض القلب والأوعية الدموية |
| **قسم العصبية** | أمراض الجهاز العصبي المركزي والمحيطي |

> **قابل للتوسع:** يمكن إضافة أقسام جديدة من لوحة التحكم دون الحاجة لتعديل الكود.

## 5. الميزات الكاملة التفصيلية

### 5.1 إدارة حسابات المرضى
- **تسجيل جديد:** بريد إلكتروني + كلمة مرور + بيانات أساسية
- **تسجيل دخول:** بريد إلكتروني + كلمة مرور
- ملف المريض الشخصي (التاريخ المرضي، المواعيد السابقة)
- عرض أقسام المستشفى مع صور الأطباء وأسمائهم وخبراتهم
- حجز موعد مباشر مع الطبيب المختار
- دفع نقدي عند الوصول (المرحلة الأولى) — إلكتروني لاحقاً
- إشعارات تذكير بالمواعيد

### 5.2 الصيدلية الإلكترونية
- متجر داخلي لشراء الأدوية المتاحة
- بحث عن الدواء بالاسم أو الفئة
- إدارة قائمة الأدوية والمخزون من لوحة تحكم مدير الصيدلية
- طلب الدواء مع خيار الاستلام أو التوصيل
- الدفع نقدي عند الاستلام (المرحلة الأولى)

### 5.3 المساعد الطبي الذكي (AI Assistant) — الفكرة المحورية

**الهدف الجوهري:**
مساعدة المريض على معرفة أي قسم طبي يناسبه بناءً على أعراضه.

**المرحلة الأولى — باستخدام GPT-4 Vision:**

**المسار 1 — تحليل الأعراض:**
1. يدخل المريض أعراضه نصياً
2. يحلل GPT-4 الأعراض ويوجّهه للقسم الأنسب
3. زر مباشر لحجز موعد في القسم الموصى به

**المسار 2 — قراءة نتائج التحاليل المخبرية:**
1. المريض يرفع صورة نتيجة التحليل
2. GPT-4 Vision يقرأ النتائج ويقدم قراءة أولية
3. توصية بالقسم المناسب + زر الحجز

> ⚠️ تنبيه دائم: التحليل استرشادي أولي ولا يُغني عن الطبيب المختص

**المرحلة الثانية (مستقبلاً) — تحليل الأشعة الشعاعية:**
- نماذج Computer Vision متخصصة (CheXNet / MONAI)
- تحليل X-Ray وMRI
- مؤجّل لما بعد نجاح المرحلة الأولى واستقرار المنصة

### 5.4 قسم التوظيف
- إعلانات الشواغر من قِبَل مسؤول التوظيف
- رفع السيرة الذاتية والتقديم المباشر
- إدارة الطلبات الواردة من لوحة التحكم

### 5.5 المحتوى التثقيفي الصحي
- مقالات ونصائح طبية وصحية عامة
- محتوى دوري موثوق للتوعية الصحية
- إدارة المقالات من لوحة التحكم (المدير العام)

## 6. نموذج الإيرادات

| مصدر الإيراد | الآلية | نسبة مقترحة |
|---|---|---|
| **حجوزات المواعيد** | عمولة على كل حجز مكتمل | 5% – 15% |

## 7. تحليل السوق — سوريا

### 7.1 واقع الرعاية الصحية الرقمية في سوريا
- السوق في مرحلة نمو مبكر في التحول الرقمي الصحي
- غالبية المستشفيات تعتمد أنظمة تقليدية أو ورقية
- طلب متزايد على الخدمات الصحية الرقمية
- انتشار متصاعد للإنترنت والهواتف الذكية في المدن الكبرى

### 7.2 الفرصة السوقية
- غياب حلول رقمية متكاملة مع دعم الذكاء الاصطناعي للسوق المحلي
- لا يوجد منافس يجمع التوجيه الذكي للمريض + الحجز + الصيدلية في منصة واحدة
- حاجة فعلية لتسهيل وصول المريض للخدمات الطبية

### 7.3 تحليل المنافسين

#### المنافس الرئيسي: شركة ATSG
| جانب المقارنة | ATSG | HealPath |
|---|---|---|
| **طبيعة المنتج** | نظام HIS تقليدي للإدارة الداخلية | منصة ويب متكاملة بذكاء اصطناعي |
| **توجيه المريض للقسم** | غير موجود | ميزة محورية بالذكاء الاصطناعي |
| **تجربة المريض** | موجهة للإداريين فقط | واجهة مريض مباشرة وسهلة |
| **الصيدلية الإلكترونية** | إداري فقط | متجر متكامل مع عمولة |
| **الذكاء الاصطناعي** | غائب | قلب المنصة |
| **التوظيف والتثقيف** | غير متوفر | مدمج بالكامل |
| **نموذج التسعير** | ترخيص مرتفع مسبق | عمولة مرنة على الأداء |

## 10. التقنيات المعتمدة للتطوير

| المكوّن | التقنية المعتمدة | السبب |
|---|---|---|
| **الواجهة الأمامية** | Next.js (React) | SSR + SEO + أداء عالٍ |
| **الواجهة الخلفية** | Node.js + Express | سرعة التطوير + مجتمع واسع |
| **قاعدة البيانات** | PostgreSQL | موثوقية عالية للبيانات الطبية |
| **المساعد الذكي** | OpenAI API (GPT-4 + GPT-4 Vision) | تحليل الأعراض + قراءة التحاليل |
| **تحليل الأشعة** | مؤجّل للمرحلة الثانية | CheXNet / MONAI |
| **الاستضافة** | AWS أو DigitalOcean (خارج سوريا) | استقرار + أمان + نسخ احتياطية |
| **المصادقة** | JWT + bcrypt | معيار الصناعة |
| **تخزين الملفات** | AWS S3 أو DigitalOcean Spaces | صور التحاليل والأشعة والسير الذاتية |
| **الإشعارات** | Email (Nodemailer / SendGrid) | تذكير المواعيد |
| **الدفع** | نقدي عند الوصول (المرحلة الأولى) | يُضاف الإلكتروني لاحقاً |

## 11. مخطط الواجهات ومسار المستخدم — UI/UX Architecture

### 11.1 الخريطة العامة للمنصة

```
┌─────────────────────────────────────────────────────────────┐
│                      HealPath Platform                      │
├──────────────────────────┬──────────────────────────────────┤
│     بوابة المريض         │      لوحة تحكم المستشفى          │
│   (Patient Portal)       │     (Hospital Dashboard)         │
│                          │                                  │
│  - الزوار (عرض فقط)      │  👤 المدير العام (كل الصلاحيات)  │
│  - المرضى المسجلون       │  👨‍⚕️ الطبيب (حجوزاته فقط)        │
│                          │  💊 مدير الصيدلية (مخزون+مبيعات) │
│                          │  📋 مسؤول التوظيف (شواغر+طلبات)  │
└──────────────────────────┴──────────────────────────────────┘
```

### 11.2 صفحة الهبوط (Landing Page) — للزوار

- Header: شعار HealPath + اسم المستشفى + أزرار (تسجيل الدخول / إنشاء حساب)
- Hero Section: عنوان تعريفي + وصف المنصة + زر CTA "ابدأ الآن"
- قسم الأقسام الطبية الخمسة (للاطلاع — بدون حجز)
- قسم الأطباء (بطاقات بصورة واسم وتخصص — للاطلاع)
- قسم المقالات التثقيفية (مرئي للجميع)
- قسم الشواغر الوظيفية (مرئي للجميع)
- Footer: معلومات التواصل + روابط سريعة

> المريض غير المسجل يستطيع الاطلاع فقط — عند محاولة الحجز يُوجَّه لتسجيل الدخول.

### 11.3 شاشات المصادقة

**تسجيل الدخول:** بريد إلكتروني + كلمة مرور + "نسيت كلمة المرور؟"
**إنشاء حساب:** الاسم الكامل + البريد + الهاتف + كلمة المرور

### 11.4 لوحة المريض الرئيسية

- شريط تنقل علوي: الرئيسية | الأطباء | الصيدلية | التوظيف | المقالات
- زر مساعد ذكي طاف (Floating) في كل الصفحات
- بطاقة ترحيبية + مواعيد قادمة + اختصارات سريعة

### 11.5 مسار حجز الموعد

```
اختيار القسم ← اختيار الطبيب ← اختيار التاريخ والوقت
← ملاحظات (اختياري) ← ملخص الحجز ← تأكيد (الدفع نقدياً عند الوصول)
← شاشة تأكيد برقم الحجز + إشعار بريد إلكتروني
```

### 11.6 المساعد الطبي الذكي (Drawer جانبي)

```
[المريض يكتب أعراضه أو يرفع صورة تحليل]
        ↓
[GPT-4 / GPT-4 Vision يحلل]
        ↓
[توصية بالقسم المناسب + الطبيب المقترح]
        ↓
[زر: احجز موعداً الآن] ← ينقل مباشرة لمسار الحجز
⚠️ تنبيه: هذا تحليل استرشادي أولي
```

**System Prompt المقترح للمساعد:**

## 15. الملخص التنفيذي النهائي

**HealPath** هو تطبيق ويب متكامل للمستشفى الذكي، يستهدف السوق السوري في مرحلته الأولى. يتميز عن جميع المنافسين بدمج الذكاء الاصطناعي في صميم تجربة المريض — لا سيما ميزة **توجيه المريض للقسم الطبي المناسب بناءً على أعراضه** وهي ميزة غائبة عن السوق المحلي تماماً.

**الركائز الأربع للمشروع:**
1. **تجربة مريض حديثة** — حجز سهل، مساعد ذكي، صيدلية إلكترونية
2. **إدارة متكاملة** — 4 أدوار واضحة الصلاحيات لكل وظيفة
3. **ذكاء اصطناعي في القلب** — GPT-4 لتحليل الأعراض والتحاليل
4. **نموذج إيرادات مرن** — عمولة مرنة بدلاً من ترخيص مسبق

**خطة التنفيذ:** 7 مراحل متسلسلة خلال ~14 أسبوعاً، بمعيار اكتمال واضح لكل مرحلة.
