## 2. هيكل المنصة

تتكون المنصة من طرفين رئيسيين متكاملين:

### 2.1 بوابة المريض (Patient Portal)
الواجهة التي يتعامل معها المريض مباشرة:
- تسجيل الحساب وإدارته
- تصفح الأطباء والأقسام وحجز المواعيد
- الدفع الإلكتروني
- الصيدلية الإلكترونية
- المساعد الطبي الذكي (تحليل الأعراض، قراءة التحاليل، الأشعة)
- المحتوى التثقيفي الصحي
- قسم التوظيف (للباحثين عن عمل)

### 2.2 لوحة تحكم المستشفى (Hospital Dashboard)
واجهة إدارية متكاملة للمستشفى:
- إدارة الأطباء والجداول والأقسام
- إدارة الحجوزات والمواعيد
- إدارة الصيدلية والمخزون الدوائي
- إدارة نتائج التحاليل والأشعة المرفوعة
- قسم التوظيف: نشر الشواغر واستقبال الطلبات وإدارتها
- لوحة إحصائيات وتقارير
- إدارة المحتوى التثقيفي

---

## 3. الميزات الكاملة للمنصة

### 3.1 إدارة حسابات المرضى
- إنشاء حساب جديد وتسجيل الدخول (البريد الإلكتروني / رقم الهاتف)
- ملف المريض الشخصي (التاريخ المرضي، المواعيد السابقة)
- عرض أقسام المستشفى، أسماء الأطباء، اختصاصاتهم ومواعيد دوامهم
- حجز موعد مباشر مع الطبيب عبر التطبيق
- دعم الدفع الإلكتروني لتأكيد الحجوزات
- إشعارات تذكير بالمواعيد

### 3.2 الصيدلية الإلكترونية
- متجر داخلي لشراء الأدوية المتاحة
- بحث عن الدواء بالاسم أو الفئة
- إدارة قائمة الأدوية والمخزون من لوحة التحكم
- طلب الدواء مع خيار الاستلام أو التوصيل

### 3.3 المساعد الطبي الذكي (AI Assistant)
- إدخال الأعراض بشكل نصي وتوجيه المريض للتخصص الطبي المناسب
- قراءة نتائج التحاليل المخبرية من صور وتحليلها أولياً
- تقديم نصائح وتوجيهات للمريض بناءً على التحليل
- تنبيه واضح: التحليل استرشادي أولي ولا يُغني عن الطبيب المختص

### 3.4 تحليل الصور الشعاعية بالذكاء الاصطناعي
- رفع صور الأشعة السينية أو الرنين المغناطيسي
- تحليل الصور باستخدام تقنيات الرؤية الحاسوبية (Computer Vision)
- الكشف الأولي عن حالات مثل الكسور أو الأورام
- ربط التحليل بالطبيب المختص داخل المنصة

### 3.5 قسم التوظيف
- إعلانات الشواغر الوظيفية من قِبَل المستشفى (أطباء، فنيون، إداريون)
- رفع السيرة الذاتية والتقديم المباشر عبر التطبيق
- إدارة الطلبات الواردة من لوحة تحكم المستشفى

### 3.6 المحتوى التثقيفي الصحي
- مقالات ونصائح طبية وصحية عامة
- محتوى دوري موثوق للتوعية الصحية
- إدارة المقالات من لوحة التحكم

## 4. نموذج الإيرادات

| مصدر الإيراد | الآلية | نسبة مقترحة |
|---|---|---|
| **حجوزات المواعيد** | عمولة على كل حجز مكتمل عبر المنصة | 5% – 15% |
| **الصيدلية الإلكترونية** | عمولة على كل عملية بيع دواء | 5% – 10% |

> **توصية استراتيجية:** في مرحلة الإطلاق، يُنصح بتخفيض العمولة أو إعفاء المستشفى منها لفترة تجريبية لضمان اعتماد المنصة. بعد إثبات القيمة، يمكن تفعيل نموذج العمولة الكامل. ويُوصى مستقبلاً بدراسة إضافة رسوم إعداد أولية أو اشتراك سنوي رمزي لضمان استقرار الإيرادات.

## 5. تحليل السوق — سوريا

### 5.1 واقع الرعاية الصحية الرقمية في سوريا
- السوق في مرحلة نمو مبكر في مجال التحول الرقمي الصحي
- غالبية المستشفيات لا تزال تعتمد أنظمة إدارة تقليدية أو ورقية
- طلب متزايد على الخدمات الصحية الرقمية بعد تداعيات الجائحة
- انتشار متصاعد للهواتف الذكية واستخدام الإنترنت في المدن السورية الكبرى (دمشق، حلب، اللاذقية)

### 5.2 الفرصة السوقية
- غياب حلول رقمية متكاملة مصممة للسوق المحلي مع دعم الذكاء الاصطناعي
- لا يوجد تطبيق يجمع الحجز والذكاء الاصطناعي الطبي والصيدلية في منصة واحدة
- حاجة فعلية لتسهيل وصول المريض للخدمات الطبية في ظل الضغط على القطاع الصحي

### 5.3 تحليل المنافسين

#### المنافس الرئيسي: شركة الأنظمة المتكاملة المتقدمة (ATSG)
**الموقع:** [atscgroup.com](https://www.atscgroup.com)

| جانب المقارنة | ATSG | تطبيق المستشفى الذكي |
|---|---|---|
| **طبيعة المنتج** | نظام إدارة مستشفيات تقليدي (HIS) | منصة ويب متكاملة بذكاء اصطناعي |
| **الذكاء الاصطناعي** | غير موجود أو محدود جداً | ميزة محورية (تشخيص، أشعة، تحاليل) |
| **تجربة المريض** | موجهة للإدارة الداخلية | واجهة مريض مباشرة وسهلة الاستخدام |
| **الصيدلية الإلكترونية** | كجزء إداري فقط | متجر متكامل مع عمولة مباشرة |
| **قسم التوظيف** | غير متوفر | مدمج بالكامل |
| **المحتوى التثقيفي** | غير متوفر | قسم متكامل |
| **نموذج التسعير** | ترخيص مدفوع مقدماً (مرتفع التكلفة) | عمولة على الأداء (مرن ومنخفض المخاطر) |
| **المستخدم المستهدف** | الإداريون فقط | الإداريون + الأطباء + المرضى |

#### نقاط التميز التنافسي للمشروع المقترح:
1. الذكاء الاصطناعي الطبي كميزة محورية لا إضافة هامشية
2. تجربة مستخدم حديثة موجهة للمريض أولاً
3. نموذج إيرادات مرن لا يُثقل كاهل المستشفى
4. الشمولية: الحجز + الصيدلية + التوظيف + التثقيف في مكان واحد
5. قابل للتطوير نحو خدمة عدة مستشفيات مستقبلاً

|---|---|---|
| **داخلي** | **نقاط القوة:** ذكاء اصطناعي متكامل، منصة شاملة، نموذج تسعير مرن، تصميم موجه للمستخدم | **نقاط الضعف:** فريق تطوير صغير (فرد)، تطلب وقتاً أطول للتطوير الكامل |

## 8. التقنيات المقترحة للتطوير

> *هذا القسم مقترح أولي قابل للمراجعة في خطة العمل*

| المكوّن | التقنية المقترحة |
|---|---|
| **الواجهة الأمامية (Frontend)** | React.js / Next.js |
| **الواجهة الخلفية (Backend)** | Node.js + Express أو Python + FastAPI |
| **قاعدة البيانات** | PostgreSQL |
| **الذكاء الاصطناعي — المساعد الطبي** | OpenAI API / نماذج مفتوحة المصدر |
| **الذكاء الاصطناعي — تحليل الصور** | TensorFlow / PyTorch + نماذج مدربة مسبقاً (CheXNet, MONAI) |
| **الاستضافة** | AWS / Google Cloud / VPS محلي |
| **بوابة الدفع** | حلول الدفع المحلية السورية المتاحة |
